# Certification Resource UI & Lang Fixes

**Type:** Bug Fix / Enhancement  
**Status:** Ready for implementation  
**Owner:** Web Engineering  
**Target Release:** v2.4.1  

---

## 1. Overview

Two small but important issues in the Trainer & Center certification management areas:

1. **Missing translation key** – `app.add_certification` is used once but not yet present in the language files.
2. **`document_code` field is editable** – the field is auto‑generated by the model (`CERT-YYYYMMDD-XXXX`), so the user must not be allowed to type or modify it.

---

## 2. User Stories

- As a **trainer/center admin**  
  I want the UI labels to be consistently translated so that I don’t see raw translation keys.  
- As a **trainer/center admin**  
  I want the system to generate the document code automatically, and I don’t want to see or edit that field.

---

## 3. Acceptance Criteria

### 3.1 Translation

- [ ] The key `app.add_certification` is added to **all** language files (English, Arabic, etc.) with an appropriate translation.  
- [ ] After adding, no raw translation key appears anywhere in the Filament UI.

### 3.2 Auto‑generated `document_code`

- [ ] In the **create** form, the `document_code` field is either:
  - Completely removed (the model’s `booted`/`creating` event will generate it automatically), or
  - Shown as a **disabled, read‑only** field with `dehydrated(false)` and a placeholder “Auto‑generated”.
- [ ] In the **edit** form, the field is either hidden or shown but **disabled** and **not updatable** (same approach).  
- [ ] The same fix applies to **both** Trainer and Center certification resources.  
- [ ] If there is an Admin/Bord certification resource, the same fix must be applied there as well.

---

## 4. Technical Implementation

### 4.1 Translation

- Search the codebase for `app.add_certification` to confirm the exact context.  
- Add to `resources/lang/en/app.php` (and other language files):
  ```php
  'add_certification' => 'Add Certification',
  ```
  (or whatever label fits the context – check how it’s used, e.g., button, title, etc.)

### 4.2 Form Schema Changes

Files to examine/modify:
- `App\Filament\Center\Resources\Certifications\Schemas\CertificationForm.php`
- `App\Filament\Trainer\Resources\Certifications\Schemas\CertificationForm.php`
- *(Optionally)* Any admin variant in `App\Filament\Admin\Resources\Certifications\Schemas\CertificationForm.php`

For each:

1. Locate the `TextInput` or `Hidden` field for `document_code`.
2. If it exists:
   - Remove it entirely (preferred) – the model’s `booted` method will set it on creation.
   - **OR** if you want to show it for reference, make it:
     ```php
     TextInput::make('document_code')
         ->label(__('app.document_code'))
         ->disabled()
         ->dehydrated(false)
         ->visible(fn ($record) => $record !== null) // show only on edit
         ->helperText(__('app.auto_generated')),
     ```
   - But ensure **it is never sent back** to the server. `dehydrated(false)` achieves this.
3. If the form uses a `Section` or `Grid`, adjust the layout accordingly.

### 4.3 Confirm Model Behaviour

- The `Certification` model already has:
  ```php
  protected static function booted(): void
  {
      static::creating(function (Certification $certification) {
          if (empty($certification->document_code)) {
              $certification->document_code = self::generateDocumentCode();
          }
      });
  }
  ```
  This works even if the field is not in the request (it will be `null` when mass‑assigning, which is empty). So removing the field from the form is safe.

---

## 6. Out of Scope

- Changing the `document_code` generation logic – it’s fine as is.
- Altering the database schema.

---

## 7. Additional Notes

- The `booted` method only generates the code if it is empty; it won’t override manually set codes (good for data imports).  
- The `document_code` column is still `fillable` because it’s needed when seeding or using the factory. That’s fine – we just prevent the UI from altering it.
